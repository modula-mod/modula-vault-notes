# Vault Product Experience 01: permission audit

This is the 2.0.2 machine permission inventory (44 IDs), audited against the current feature branch. “Core workflow” and “Optional / audit” are implementation classifications, not manifest flags: `module.manifest.json` has no per-ID required marker. The MPS source has five broad required categories, which do not map one-to-one onto these IDs. Actual personal and QA grants have not been queried; no grant was changed.

Greenfield record requests are checked against the installed release and account by `runtime-access.ts` and `record-service.ts`. Native sends the signed-in session through `GreenfieldClient.moduleRequest`; it does not expose tokens to a module. The attachment upload first uses the account media service, then the module media binding service checks record and media write grants. A declared ID alone does not prove a working native or server flow.

## Audit decisions before release

- Keep the note, folder, tag and note media record grants only when their end-to-end QA paths pass. A physical phone screen rendering is insufficient evidence.
- Review `search:index`: current `q` search reads `greenfield_module_records.search_text`, derived from declared searchable fields including `plainTextProjection`; an additional publisher-side index workflow was not found in this audit.
- Reassess registration, event, legacy attachment-metadata, note-version, saved-source, template, saved-search, notifications, jobs, widget, sharing and temporary-file IDs. They must not be presented as functioning features without accepted handlers and UI. Remove unnecessary requests in MPS first, then regenerate adapter permissions for the candidate.
- Unknown IDs remain reviewable by permission family and fail at the execution boundary. Do not auto-grant them to a personal account.
